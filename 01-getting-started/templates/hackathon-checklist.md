# Hackathon Checklist Template

Print this. Check the boxes. Don't lose.

---

## Phase 1: Pre-Hackathon (1–7 days before)

- [ ] Registered for the hackathon (confirmation email saved)
- [ ] Read the rules, judging criteria, and submission requirements
- [ ] Checked sponsor tracks and bonus prizes
- [ ] Team assembled (or decided to go solo)
- [ ] Team roles assigned: frontend, backend, design, pitch
- [ ] Problem idea chosen (used the Problem Scorecard)
- [ ] User persona defined (who is this for, what's their pain)
- [ ] MVP scope locked (what ships in 24h/48h/72h — no more)
- [ ] Tech stack decided (used the Stack Decision Tree)
- [ ] Dev environment set up locally (clone, install, run works)
- [ ] Starter repo created on GitHub with README
- [ ] API keys obtained (OpenAI, Stripe, Twilio, etc.)
- [ ] Figma / design mockup roughed out (even napkin sketches)
- [ ] Deployment target chosen (Vercel, Railway, Fly.io)
- [ ] Backup plan written (what if your main idea fails?)
- [ ] Snacks, water, and comfort items ready
- [ ] Calendar blocked — no interruptions for hackathon duration

---

## Phase 2: Day Of (First 2 Hours)

- [ ] Arrived early or logged into livestream on time
- [ ] Network with other hackers — exchange Discord handles
- [ ] Listen to opening ceremony and sponsor presentations
- [ ] Confirm team roles and communication channel (Discord/Slack)
- [ ] Set up shared workspace (GitHub org, Figma, task board)
- [ ] Write down exact MVP deliverables on a shared doc
- [ ] Time-box the day: break into 2–3 hour work blocks
- [ ] Build the core data model / database schema first
- [ ] Get a "hello world" deployment running on your target platform

---

## Phase 3: Building (Core Hackathon Hours)

- [ ] Backend API endpoint returns data (even hardcoded)
- [ ] Frontend connects to backend (even ugly — beauty later)
- [ ] Authentication working (or deferred with a clear plan)
- [ ] One complete user flow end-to-end (even minimal)
- [ ] Commit and push every 1–2 hours (don't lose work)
- [ ] Test on mobile if it's a web app
- [ ] Integrate at least one sponsor API / tool
- [ ] Apply basic styling (Tailwind or CSS framework)
- [ ] Fix blocking bugs before polishing
- [ ] Start recording demo video or screenshots
- [ ] Write submission description (problem, solution, tech, impact)
- [ ] Prepare pitch script (3 min max, practice twice)

---

## Phase 4: Final 4 Hours (Submission Crunch)

- [ ] Deploy to production (not just localhost)
- [ ] Test deployed version end-to-end
- [ ] Fix any broken links or images
- [ ] Record demo video (2–3 min, show the product working)
- [ ] Upload video to YouTube or Loom
- [ ] Fill out submission form completely
- [ ] Double-check: repo is public, README is complete
- [ ] Submit — screenshot the confirmation
- [ ] Backup: save submission URL, video link, and repo link somewhere safe

---

## Phase 5: Post-Hackathon (Within 48 Hours)

- [ ] Thank teammates (genuinely, not just a group message)
- [ ] Clean up repo (add README, comments, remove dead code)
- [ ] Share project on Twitter/LinkedIn with hackathon hashtag
- [ ] Connect with judges and mentors on LinkedIn
- [ ] Write a short blog post or tweet thread about what you built
- [ ] Note lessons learned for next hackathon
- [ ] Apply for any post-hackathon programs (accelerators, grants)

## Time-Boxed Survival Guides

### 24-Hour Hackathon
| Block | Time | Focus |
|-------|------|-------|
| 1 | Hours 0–2 | Plan, design, set up repo |
| 2 | Hours 2–8 | Core backend + frontend scaffold |
| 3 | Hours 8–14 | Build the main feature end-to-end |
| 4 | Hours 14–20 | Polish, style, fix bugs |
| 5 | Hours 20–24 | Deploy, record demo, submit |

### 48-Hour Hackathon
| Block | Time | Focus |
|-------|------|-------|
| 1 | Hours 0–3 | Ideation, scoring, architecture |
| 2 | Hours 3–10 | Backend MVP (data model, 2–3 endpoints) |
| 3 | Hours 10–18 | Frontend MVP (all screens, wire it up) |
| 4 | Hours 18–28 | Integration, auth, sponsor APIs |
| 5 | Hours 28–38 | Polish, edge cases, mobile responsive |
| 6 | Hours 38–45 | Deploy, demo video, submission |
| 7 | Hours 45–48 | Buffer for disasters + submit |

### 72-Hour Hackathon
| Block | Time | Focus |
|-------|------|-------|
| 1 | Hours 0–4 | Deep ideation, scorecard, architecture doc |
| 2 | Hours 4–16 | Full backend with real data |
| 3 | Hours 16–32 | Full frontend with multiple views |
| 4 | Hours 32–48 | Integration, testing, sponsor track |
| 5 | Hours 48–60 | Polish, animations, micro-interactions |
| 6 | Hours 60–68 | Deploy, record, write submission |
| 7 | Hours 68–72 | Buffer, rehearsal, submit |

## Emergency Checklist (When Things Go Wrong)

**Your project won't deploy:**
- [ ] Check environment variables — are they set on the platform?
- [ ] Check build logs for the exact error
- [ ] Try a different platform (Vercel → Railway → Fly.io)
- [ ] Fall back to GitHub Pages with a static version

**Your API is broken / rate limited:**
- [ ] Mock the data with hardcoded JSON
- [ ] Switch to a free tier on a different provider
- [ ] Use a local SQLite database instead

**Teammate ghosted:**
- [ ] Take ownership of the most critical path
- [ ] Cut scope ruthlessly — one feature, done well
- [ ] Solo hacks win too — you've got this

**You're behind schedule:**
- [ ] Cut features to the absolute minimum
- [ ] Skip styling — make it functional
- [ ] Use a boilerplate / template for the UI
- [ ] Focus on the demo video — that's what judges see first

**You're exhausted:**
- [ ] Take a 20-minute nap (set an alarm)
- [ ] Walk outside for 5 minutes
- [ ] Switch to a different task to stay fresh
- [ ] Coffee, water, food — in that order
